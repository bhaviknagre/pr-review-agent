1Executive summary

PR Review Agent is a GitHub App. When a pull request is opened, updated, reopened or marked ready for review, it clones the code, runs the repository's own tests inside a hardened Docker sandbox, and reviews the diff with a language model through LiteLLM. The model is a local Ollama model by default, or any provider you give a key for. The agent correlates findings with failing tests and posts one review with inline comments and suggested fixes.

It runs on your own infrastructure. Source code goes to the model you configure and nowhere else, and the agent sends no telemetry.

Goals achieved

  • One review per commit, even when workers crash, Redis restarts or GitHub returns errors.
  • Untrusted code runs only in a sandbox with no network, a read-only root and dropped capabilities.
  • Test evidence and model findings appear together, so a failing test raises the severity of the finding that explains it.
  • Operators can see every job, retry, cost and dead-lettered failure through an admin API and CLI.

2System architecture

2.1Components

The system is two long-running processes and one migration job, backed by Postgres and Redis. Postgres is the source of truth. Redis only delivers job ids to workers.

2.3Design patterns

  • Durable job before 2xx. The webhook persists the job, then enqueues it. A lost enqueue is repaired by the sweeper.
  • Idempotent stages. Each attempt is a stage_attempts row, so a restarted job resumes after the last finished stage.
  • Lease and heartbeat. A worker holds a lease (300 s default) on a running job. A sweeper re-queues jobs whose lease expired.
  • Supersede. A new head SHA on the same PR marks older jobs superseded, under a per-PR advisory lock.
  • Dead-letter queue. Jobs that exhaust retries or pass the deadline stop in dead_letter and can be requeued.
  • LLM resilience. Circuit breaker, retries and fallback models, plus a per-job and a daily USD budget.
  • Effectively-once posting. A Postgres advisory lock wraps posting, and a hidden SHA marker in the review body lets a retry find and adopt an existing review.
  • Allowlist-only egress. Dependency install runs behind a proxy that permits only package-registry hosts.

3Review pipeline

3.1Stages

Timeouts come from pipeline/lease.py. Retry policies come from pipeline/retry.py and are written as attempts, backoff base and cap in seconds, with full jitter. The job as a whole must finish within JOB_DEADLINE_SECONDS (3600 by default), or it is dead-lettered.

StageTimeoutRetryWhat it does
fetch120 s5, 1 s, 60 sReads PR metadata and diff from GitHub, clones the head commit, and checks it still matches the job's SHA. Rejects diffs over 2,000,000 bytes or 300 files.
detect60 s3, 1 s, 30 sFinds projects and languages, applies .pr-review.yml, and chooses test commands.
test900 s2, 5 s, 120 sInstalls dependencies behind the egress proxy, then runs tests in the sandbox with no network. Each run has its own timeout (300 s by default).
parse60 s2, 1 s, 30 sParses test reports and coverage, and splits the diff into model-sized chunks.
analyse1200 s4, 2 s, 120 sRuns deterministic checks, then asks the model for findings per chunk and category. Output is validated against a strict schema.
aggregate60 s3, 1 s, 30 sCorrelates findings with failing tests, removes duplicates, applies repo filters, picks the review event.
post120 s5, 2 s, 60 sPosts one review with inline comments and suggestion blocks, under the posting lock.

The analyse timeout is the setting ANALYSE_TIMEOUT_SECONDS. It is long on purpose, because local models are slow. Retryable errors include timeouts, transport errors, GitHub rate limits and 5xx responses, and a lost lease. Other errors go straight to the dead-letter queue.

3.2Job state machine

Succeeded, superseded and cancelled are final. Dead-letter is final except for the operator requeue edge, which clears the dead-letter reason. Illegal moves raise TransitionError.

4Security model

The agent runs code from pull requests, so it assumes every repository input is hostile.

GitHub App permissions

The App requests the minimum: pull requests write, contents read, metadata read.

Webhook ingress

  • The HMAC-SHA256 signature is checked on the raw body before any JSON is parsed.
  • Bodies over 5 MiB are rejected, both by the declared length and while streaming.
  • Rate limits are fixed 60-second windows in Redis: 60 requests per IP and 120 per installation. The installation key is used only after the signature passes.
  • If Redis is down the limiter fails open, so deliveries are not lost. This is intentional and documented.
  • Only the actions opened, synchronize, reopened and ready_for_review create jobs. Duplicate delivery ids are ignored.

Sandbox

ControlSetting
Networknetwork_mode=none for test runs
FilesystemRead-only root; writable tmpfs /tmp and a per-run output directory
PrivilegesAll capabilities dropped; no-new-privileges; non-root user; default seccomp
ResourcesPID limit (128), memory (512 MiB default), CPUs (1.0 default), ulimits, no swap, killed on timeout
EnvironmentEmpty, plus an explicit allowlist. The host environment is never forwarded.
ImagesOnly pinned tags in an allowlist: the four sandbox images plus python:3.12-slim and alpine:3.20

For stronger isolation, run Docker rootless or use the gVisor runtime for the sandbox containers.

Egress proxy for dependency install

Install is the only step with network access. It runs on a per-run internal Docker network that contains a single proxy container, which allows only CONNECT host:443 to registry hosts: pypi.org, files.pythonhosted.org, registry.npmjs.org, proxy.golang.org, index.crates.io and static.crates.io. Set SANDBOX_PIP_INDEX_URL to use a private index. Installed packages are copied out, and the tests then run with no network.

Model input and output

  • Prompt-injection guard (llm/guard.py). Untrusted blocks are re-delimited with a per-request nonce, delimiter-like text is neutralised, injection signals are counted and logged, and only system and user roles are sent. No tools are given to the model. Payload text is never logged, only counts.
  • Secret redaction (core/redaction.py) runs over all content before it reaches a model.
  • Persistence sanitiser (storage/sanitize.py) cleans text at the database boundary, so error messages and reasons cannot carry source or diff text.

Data handling

Job data is purged after RETENTION_DAYS (30 by default) by a daily job at RETENTION_HOUR_UTC (03:00 by default). The admin API is disabled until ADMIN_TOKEN is set, and then requires a Bearer token. There is no telemetry.

5Code review highlights

Before release we audited the whole code base and ran it against real services. This section records what held up, what we fixed, and the measured results.

5.1Strengths

  • Postgres is the single source of truth. Redis loss delays work but does not lose it.
  • State transitions are guarded updates with an event written in the same transaction, so history is always consistent.
  • Model output is validated against a frozen, versioned schema. Findings that do not anchor to a changed line are rejected and counted, not hidden.
  • Deterministic checks (secret scan and patterns) run beside the model and take precedence over it.
  • Strict typing (mypy --strict) and a coverage gate in CI.

5.2Defects found and fixed during final verification

a) Worker killed long LLM stages. arq applies a 300 s default job timeout, shorter than the analyse stage allows. The worker now uses the job deadline.

Before
class WorkerSettings:    max_jobs = CFG.worker_max_jobs    keep_result = 0
After
class WorkerSettings:    max_jobs = CFG.worker_max_jobs    job_timeout = CFG.job_deadline_seconds    keep_result = 0

b) A model finding could hide a deterministic one. De-duplication ranked overlapping findings by severity only, so a CRITICAL model finding could silently replace a static SQL-injection finding. Deterministic findings now sort first (review/correlate.py).

Before
out.sort(key=lambda p: (    SEVERITY_ORDER.index(p[0].finding.severity),    p[1], ...))
After
out.sort(key=lambda p: (    DETERMINISTIC.match(p[0].finding.summary) is None,    SEVERITY_ORDER.index(p[0].finding.severity),    p[1], ...))

c) Duplicate reviews after a lease was reclaimed during a GitHub outage. Two workers could both reach the post step. Posting now runs under a Postgres advisory lock on (repo, PR, SHA) in DbReviewStore.exclusive. Inside the lock, a review already carrying the SHA marker is recorded through _adopt instead of being created again.

connectors/github/posting.py
async def post(self, pr, head_sha, plan, summary_md, suggestions):
    lock = self._store.exclusive(pr.repo, pr.number, head_sha) if self._store else nullcontext()
    async with lock:
        return await self._post_locked(pr, head_sha, plan, summary_md, suggestions)

d) Out-of-memory runs were not detected on cgroup v2. Docker reported OOMKilled=false when a child process was killed. The sandbox only sends SIGKILL on timeout, so an exit code 137 without a timeout is now treated as the memory limit.

Before
oom = bool(state.get("OOMKilled"))
After
oom = bool(state.get("OOMKilled")) or (code == 137 and not timed_out)

e) The container image had no git. The worker clones with the git CLI, so every clone failed in the packaged image. The runtime stage of the Dockerfile now installs git and CA certificates.

f) Three filelock CVEs in a transitive dependency. litellm capped filelock below 4.0, and every 3.x release carried open advisories. filelock is used only through model-hub caching, whose API is unchanged in 4.x, so we override the cap.

pyproject.toml
[tool.uv]
override-dependencies = ["filelock>=4.2.1"]

g) Admin requeue bypassed the state machine. It wrote the status directly. DEAD_LETTER to QUEUED is now an explicit edge in TRANSITIONS, and requeue goes through state.transition, so the event log and lease fields stay correct.

pipeline/state.py
DEAD_LETTER: frozenset({QUEUED}),   # operator requeue override

6.4Findings and repository config

A finding has these fields: severity (CRITICAL, MAJOR, MINOR, INFO), category (correctness, security, performance, style), file_path, line_start, line_end, summary (up to 300 characters), rationale (up to 2000), optional suggestion (up to 4000) and confidence (0 to 1).

Place a .pr-review.yml in the repository root to tune a review:

KeyMeaning
test_commandsCommands keyed by project folder; . is the repo root.
test_timeout_secondsLowers the test time budget. It cannot exceed the operator's limit.

categoriesWhich categories to report.
min_severityLowest severity to post. Default INFO.
tests_disabledSkip the test stage. Default false.

test_commands:
  ".": ["pytest", "-q"]
  "web": ["npm", "test"]

ignore: ["docs/**"]

7Quality engineering

Testing approach

Tests use real services. They run against Postgres, Redis, a Docker daemon, a real Ollama server and a local HTTP server that injects faults. End-to-end tests use a real GitHub App. Core services are not mocked.

MarkerNeeds
dockerA Docker daemon
llmA real Ollama server
githubThe real GitHub API
e2eFull webhook-to-posted-review flow
perfBenchmarks, run explicitly
loadFault-injection load tests, run explicitly

Continuous integration

The ci workflow runs on pushes to main and on pull requests. It runs these steps in order:

  1. ruff check on src and tests.
  2. mypy src in strict mode.
  3. pytest with qwen2.5-coder:0.5b served by Ollama, excluding load and perf, and failing under 85% coverage.
  4. pip-audit on locked dependencies.
  5. A check that no TODO markers remain.

Load and performance tests run on demand. The main branch requires the ci check and forbids force pushes.

AAppendix: Glossary

Lease
A time-limited claim a worker holds on a running job. If it expires, the sweeper re-queues the job.
Supersede
Mark an older job obsolete because a newer commit arrived on the same pull request.
Dead letter
The state of a job that exhausted its retries or deadline. An operator can requeue it.
Deterministic finding
A finding from a rule-based check (secret scan or pattern check) rather than from the model. It wins over an overlapping model finding.
Marker
A hidden comment holding the reviewed commit SHA in a posted review. It lets a retry find an existing review instead of posting a second one.
