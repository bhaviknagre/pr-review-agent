Setup & Deployment Guide

PR Review Agent reviews every pull request in your GitHub repositories: it runs your tests in a secure sandbox, reviews the change with AI, and posts one review with inline comments. No workflow files, no code changes in your repo.

Overview

Your repositories need no workflow file and no secrets: you install the GitHub App, and every pull request is reviewed automatically.

Runs your tests

Detects Python, JavaScript/TypeScript, Go and Rust projects and runs their tests in an isolated sandbox.

AI review

Finds correctness, security, performance and style issues, and links them to failing tests.

One clean review

One review per commit, with inline comments and one-click suggested fixes.

Option A: Hosted (about 2 minutes)

You need admin rights on the repositories (or the organization) you want reviewed.

  1. Open the install link: https://github.com/apps/pr-review-agent-github/installations/new.
  2. Pick your personal account or organization.
  3. Choose Only select repositories and tick the repos to review (or All repositories).
  4. Review the permissions and click Install:
    • Pull requests: Read and write (to read the PR and post the review)
    • Contents: Read-only (to check out the code and run its tests)
    • Metadata: Read-only (required by GitHub)

That's it. The next pull request in those repos is reviewed automatically.

Add or remove repos later: GitHub Settings → Applications → Installed GitHub Apps → PR Review Agent → Configure (for an organization, its Settings → GitHub Apps).

Option B: Self-hosted (manual setup)

Run the agent on your own server. Steps 1 to 3 are done once; step 4 for each repository you add.

Step 1: Create your GitHub App

Where: the App is created in your GitHub account or organization settings, not inside any repository. Your repositories only receive an install (step 4).
  1. Go to Settings → Developer settings → GitHub Apps → New GitHub App (organization settings for an org-owned App).
  2. Webhook: tick Active. URL https://<your-server>/webhook/github. Secret: a long random string, e.g. openssl rand -hex 32; keep it.
  3. Repository permissions: Pull requests Read and write, Contents Read-only, Metadata Read-only.
  4. Subscribe to events: Pull request only.
  5. Where can this App be installed: Only on this account.
  6. Click Create GitHub App, note the App ID, then Generate a private key (downloads a .pem file).

Triggers: pull requests that are opened, synchronized (new commits), reopened or ready_for_review. A new push cancels that PR's review still in progress and reviews the new commit.

Step 2: Configure secrets (.env)

All secrets live in the server's .env file, never in your repositories. Start with cp .env.example .env.

Step 3: Deploy

git clone https://github.com/bhaviknagre/PR-REVIEW-AGENT-.git pr-review && cd pr-review
cp .env.example .env              # fill in step 2 values
./docker/sandbox/build.sh         # python, node, go, rust sandbox images
ollama pull qwen2.5-coder:7b
ollama pull qwen2.5-coder:1.5b
docker compose up -d --build
curl -fsS http://localhost:8000/healthz   # {"status":"ok"}
  • Start order is automatic: database and queue first, then migrations, then the API and worker.
  • Put a TLS reverse proxy in front of port 8000. Expose only /webhook/github; keep /admin and /metrics internal.
  • Scale with docker compose up -d --scale worker=N; each worker handles 4 reviews at once by default.
  • Upgrade with git pull && docker compose up -d --build; migrations run automatically.

Step 4: Install on your repositories

  1. Open your App's page: Settings → Developer settings → GitHub Apps → your App → Install App.
  2. Click Install, choose Only select repositories, and pick the repos to review.

Optional: to block merges on critical findings, enable Require a pull request review in branch protection and set REQUEST_CHANGES_ON_CRITICAL=true.

CI/CD: your repositories need no CI changes. The agent runs as a GitHub App, not as a GitHub Action, so it uses no runner minutes or repository secrets.

Tune reviews per repository (optional)

The agent detects your project type and test command on its own. To change its behaviour, add .pr-review.yml at the root of a repository:

test_commands:
  ".": ["pytest", "-q"]        # "." = repo root; another folder for a sub-project
  "web": ["npm", "test"]       # a second project in the web/ folder
test_timeout_seconds: 180
ignore: ["docs/**", "migrations/**"]
categories: [correctness, security, performance]   # also: style
min_severity: MINOR            # CRITICAL | MAJOR | MINOR | INFO
tests_disabled: false

All keys are optional. An invalid file never blocks a review: the agent uses its defaults and says so in the review summary.

Check it works

  • Open a pull request in an installed repository (a small change is enough)
  • Within a few minutes, the PR shows one review from PR Review Agent
  • The review summary lists your test results and findings by severity
  • Findings on changed lines appear as inline comments, some with a suggested fix
  • Push another commit: a fresh review is posted for the new commit

Self-hosted extras: /healthz returns {"status":"ok"}, /readyz returns 200, and the App's Advanced → Recent Deliveries shows 202 for each pull request.

Security and your data

  • Least privilege: the App can read pull requests and code and post reviews. It cannot push code, merge, change settings, or read other repositories.
  • Isolated test runs: tests run in a locked-down container with no network except approved package registries, strict memory and CPU limits, and nothing kept after the run.
  • Secrets stay out: credentials found in code are masked before anything is stored or posted.
  • Where code goes: only to GitHub and the configured AI model. Self-hosted with Ollama, your code never leaves your server. No telemetry.
  • Retention: job records are deleted automatically after 30 days.
  • Remove access any time: uninstall the App from GitHub Settings → Applications; reviews stop at once.

Troubleshooting

SymptomCause and fix
No review after 15 minutesCheck the App is installed on that repository. Self-hosted: check the worker logs (docker compose logs worker).
Webhook delivery shows 401The webhook secret differs between the App and .env; make them identical and restart.
Delivery shows 202 ignoredNormal for events that are not reviewed.
Database restarts on first start.env is missing; create it, then docker compose down -v && docker compose up -d (fresh installs only).
Worker unhealthyWrong DOCKER_GID; use stat -c %g /var/run/docker.sock on Linux or 0 on macOS Docker Desktop.
Review times outSlow CPU-only AI model; raise ANALYSE_TIMEOUT_SECONDS, use a GPU, or a hosted model.
Dependency install times outThe server cannot reach PyPI quickly; check network access or set SANDBOX_PIP_INDEX_URL to a mirror.
